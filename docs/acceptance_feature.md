# 실행 전 완료 조건과 결과물 검사 — 2026-09-06 추가

## 문제와 결정
기존 evaluator는 명령 출력과 LLM 판단으로 완료 여부를 정했다. 성공처럼 보이는 출력이 나와도 요청한 파일이 빠질 수 있다. 사용자가 실행 전에 완료 조건 JSON을 정하고, planner가 매 시도 볼 수 있게 전달한다. 실제 파일 검사 결과를 history에 기록해 다음 계획에 반영한다. 세 번 실패하면 종료한다.

지원 검사: 비어 있지 않은 파일, 필수 문구, CSV 필수 컬럼·행 수·컬럼 수 정합성, JSON 최상위 키·기대값. 조건 JSON은 실행 중 모델이 수정하지 않는다. 임의 검증 명령을 실행하는 대신 정해진 읽기 검사만 지원한다.

```bash
.venv/bin/python demo_acceptance.py
.venv/bin/python -m unittest discover -s tests -v
AGENT_WORKDIR=/tmp/my-agent-run .venv/bin/python agent.py \
  --acceptance examples/acceptance.json --report-json /tmp/my-agent-report.json --no-slack \
  '예제 데이터로 season_counts.csv에 season,matches 컬럼과 2021~2025 다섯 행을 만들고 summary.md에 ## 결과 및 ## 한계를 쓰세요.'
```

데모: 첫 시도에 CSV 한 행만 작성 → 행 수 부족·요약 누락 확인 → 두 번째 시도에 5행과 요약 작성 → 통과. 데모 planner는 고정 응답이고 실행·검사는 실제다. 이를 LLM 정확도 개선 수치로 쓰면 안 된다.

## 한계
- 완료 조건 통과는 내용의 사실성·연구의 타당성을 보증하지 않는다. 오래된 결과물이 조건을 만족할 수도 있으므로 실행마다 비어 있는 작업 폴더를 권장한다.
- 기준이 부실하면 검사도 부실하다. 현재 버전은 사용자가 조건을 직접 정한다.
- `definer.py`의 자유 형식 verification_command를 자동 실행하지 않는다. `--acceptance`는 별도의 명시적 JSON 입력이다.
- 기존 executor의 정규식 제한은 격리된 샌드박스가 아니다. 신뢰할 수 있는 작업과 별도 작업 폴더에 사용하는 로컬 프로토타입이다.
- 체크포인트·중단 후 재개·상용 운영은 이번 변경 범위가 아니다.
